# Касса объектов

Учёт финансов по строительным объектам: объект → этапы → лента операций,
автоматический бонус с каждого прихода, доли 75 / 15 / 10, касса и дебиторка.
Реализация ТЗ от 17.09.2026 — версии 1 и 2 из раздела 13.

## Запуск

```bash
npm install
npm run dev
```

Приложение поднимется на http://localhost:3000. База создаётся сама в `.data/finance.db`
и на первом запуске наполняется контрольным примером из раздела 14 ТЗ
(«Ресторан, Конибодом», договор 18 000, ставка 10 %).

Сборка и запуск в продакшене:

```bash
npm run build
node .output/server/index.mjs
```

Проверка расчётного ядра:

```bash
npm run check
```

Проверка API на живом сервере с временной базой (сборка + тесты):

```bash
npm run test:api
```

## Учётные записи по умолчанию

Пароль совпадает с логином, все помечены как временные. Пока пароль не
заменят на экране «Профиль», сервер не отдаёт никаких данных и не принимает
записей — открыт только профиль со сменой пароля.

Учётные записи: `owner`, `ilhom`, `ulugbek`, `prorab`, `buh`.

**Роли — две** (`ROLE_MODE = 'simple'` в `shared/roles.ts`):

| Роль | Кто | Что может |
|---|---|---|
| Администратор | `owner` | всё: сторно, «Исправить», закрытие этапов, объекты, справочники, пользователи |
| Оператор | остальные | видит всё, вносит приходы, расходы, авансы, отмечает бонус |

Режим `'off'` — ролей нет, у всех права администратора; `'full'` — четыре роли
из ТЗ с урезанием видимости (прораб видит только кассу и свои расходы и т. д.).

**Смените пароли перед тем, как открывать приложение за пределы своего компьютера.**

## Устройство

| Каталог             | Что там                                                          |
|---------------------|------------------------------------------------------------------|
| `shared/calc.ts`    | расчётное ядро — один код на сервере и на клиенте                 |
| `shared/roles.ts`   | роли и правила видимости из раздела 3                             |
| `shared/i18n.ts`    | словарь русский → узбекский                                       |
| `shared/mask.ts`    | маски ввода: сумма, курс, процент, телефон, код валюты, логин     |
| `server/utils/`     | база (`node:sqlite`), сессии, проверки, проекция под роль, копии   |
| `server/api/`       | состояние, операции, объекты, этапы, справочники, файлы, выгрузка  |
| `app/`              | экраны, формы, стили                                              |
| `test/`             | приёмка из раздела 14, инварианты расчёта, маски и переводы        |

Ответы API сжимаются gzip'ом: состояние на несколько тысяч операций — это
мегабайты JSON, а по вай-фаю с телефона они едут секундами. На 21 тысяче
операций это 9 МБ против 128 КБ.

Деньги везде — целые числа центов. У операции две суммы: в валюте операции
и в валюте объекта по курсу на дату; в расчёт идёт вторая.

## Язык

Переключатель RU / UZ стоит в шапке и в профиле, выбор хранится в куке `lang`
и виден серверу при отрисовке страницы. Ключ перевода — сам русский текст,
поэтому строка без перевода показывается по-русски, а не как «settings.title».
Новые надписи добавляются в `shared/i18n.ts`; тест следит, чтобы в переводах
не терялись подстановки вида `{amount}`.

Имена людей, названия объектов и комментарии не переводятся — это введённые
данные, они остаются как есть.

## Два типа расходов

**Прямой расход объекта** уменьшает чистую долю и относится к команде —
направлению работ: архитекторы, дизайнеры, конструкторы, инженеры.
Бывает мультикоманда: один исполнитель закрывает несколько направлений сразу,
у неё перечислен состав.

**Расход не по объекту** к объекту не относится и записывается авансом
участнику дележа с указанием назначения. Чистую долю он не трогает — это
деньги самого участника, — но кассу уменьшает и попадает в его авансы.
В ленте такие строки помечены.

## Люди и команды

Человек в справочнике привязан к команде: Шухрат ака — архитекторы,
Пархаёт ака — конструкторы. Список «Люди» разложен по командам, внизу —
те, кто ни в одной не состоит (нозир, участники дележа).

Отсюда работает форма расхода: сначала выбирают команду, и только потом
появляются её люди. Выбрали дизайнеров — архитектор в списке не покажется.
Без команды предлагаются внештатные. У мультикоманды в списке ещё и люди
её направлений.

В карточке человека четыре числа: причитается, получено, ещё не получил
и следующий платёж. Для человека команды «причитается» — его собственная
сумма внутри плана команды, а если она не назначена — весь план команды
(об этом сказано прямо под плитками). Для участника дележа — начисленная доля.

Следующий платёж — ближайший незакрытый этап, где команде ещё
выделены деньги: «после этапа 2». Если и этого нет, а долг остался,
так и написано: срок не назначен.

## Категории расходов

Категория показывается там, где нужна. У команды свои работы: у архитекторов —
эскизный проект, планшеты, 3D, рабочие чертежи, авторский надзор; у дизайнеров,
конструкторов и инженеров — свои. Выбрали команду — в списке её работы плюс
общие по объекту (материалы, подряд, аренда, транспорт). Чужие не появятся.

Расход не по объекту сначала спрашивает группу — офис, личное, транспорт,
прочее, — и дальше показывает только её категории: коммунальные, интернет,
вода и напитки, хозтовары, канцелярия и так далее.

Команда, человек и категория выбираются чипсами — видно сразу весь выбор.
Нужного в списке нет — там же чип «Добавить»: имя, «Добавить», и он выбран.
Человек заводится сразу в выбранную команду, категория — у выбранной команды
или в выбранной группе. Получателя бонуса в карточке объекта так же можно
завести на месте. В справочниках категории разложены по тем же местам,
область каждой меняется списком, новая группа заводится оттуда же.

## План расходов по командам

С командой договариваются об общей сумме на объект — это план. Из плана на
каждый этап выделяют часть: «договорились с архитекторами на 5 000, с первого
этапа даём 2 000». Дальше видно три числа: план, выделено, потрачено.
Выделить на этапы больше, чем есть в плане, система не даёт; без плана
выделять не из чего. Урезать план ниже уже выделенного на этапы или
расписанного по людям тоже нельзя.

План команды делится на людей: кнопка «По людям» в таблице плана открывает
список команды, и там каждому ставится своя сумма. Расписать больше, чем весь
план команды, нельзя — и форма, и сервер отказывают. Нерасписанный остаток
подписан прямо в строке команды.

Своя сумма человека важнее общей: в его карточке «причитается» — это она,
а не весь план команды. Пока сумма не назначена, показывается план команды,
и под плитками об этом сказано.

На карточке объекта — таблица «Команды и план расходов» со сводкой и остатком.
Внутри этапа — «Выделено командам на этап» с полосой закрытия по каждой команде.

Строка команды остаётся, пока по ней есть проведённые расходы: это факт, а не
план, и убрать его можно только сторно операции. В такой строке написано
«расход проведён без выделения», и корзины у неё нет — убирать нечего.

## Доли, бонус и закрытие этапа

**Доли считаются от реально полученных денег:** чистая доля этапа =
приход − расходы. Пока заказчик заплатил часть, делится только то, что пришло.
Дебиторка по-прежнему считается от суммы этапа по договору.

**Бонус** появляется строкой сразу с приходом, но в расходы и доли идёт только
после кнопки «Получено» в ленте. Пока не получен — деньги числятся в кассе,
строка подписана «не получен». При отметке спрашивается дата получения.
Отметку можно снять, пока этап не на сверке. Этап с неполученным бонусом
не закрывается. Неполученный бонус лежит в кассе, но это не свободные деньги:
под кассой написано «свободно N», а расход или аванс сверх свободного
вызывает предупреждение.

**Закрытие этапа:** дебиторка ноль, бонус получен, касса ноль — жёсткие
условия. Кроме того, у каждого участника «к доплате» должно быть ноль:
касса ноль значит «ноль в сумме», а одному могли переплатить за счёт
другого. Такой перекос можно принять только явно — «Закрыть с расхождением»
с причиной, она пишется в журнал.

**«Исправить»** (администратор): форма открывается заполненной записью;
при сохранении старая запись сторнируется и новая ложится одной транзакцией.
Фото чека остаются у старой записи.

**Двойная отправка** не создаёт дубль: у каждого открытия формы свой ключ,
повтор с тем же ключом возвращает уже созданную запись. Предупреждение
«не дубль?» срабатывает и без человека — по категории, сумме и дате.

**Статусов у записи два:** проведено и отменено (сторно). Обещаний больше нет:
при обновлении старые записи «обещано» отменяются с причиной «статус упразднён».
Сторно в ленте скрыты, показываются кнопкой «Показать сторно».

На карточке объекта у каждого участника своя карточка: крупно — сколько
ему осталось получить по прогнозу (договор минус проведённые расходы,
минус неизрасходованный остаток планов, минус бонус впереди — неполученный
и будущий, по ставке объекта с ещё не оплаченной части договора), ниже — по этапам: получено и
осталось. Внутри этапа — только этот этап.

У каждого этапа есть полоса закрытия. Она складывается из двух движений:
сколько получено от заказчика и сколько выплачено участникам. Сто процентов —
когда заказчик рассчитался и деньги разошлись: дебиторка ноль, бонус получен, касса ноль.

## Сводка за период

Раздел «Отчёты» — аналитика за период по всем объектам сразу. Период берётся
кнопкой (месяц, квартал, год, всё время) или руками; можно сузить до одного
объекта. Показывает приход, расходы, авансы и движение денег, столбики по
месяцам, разбивку по объектам, командам, людям и категориям расходов.

Объекты бывают в разных валютах, поэтому всё сводится в валюту экрана
(переключатель USD / SUM), и каждая операция — по своему курсу на свою дату.

## CRM: клиенты

Раздел «Клиенты» — карточка с ФИО, телефонами, почтой, источником
(рекомендация, повторный, инстаграм, сайт, выставка) и комментарием.
В карточке видны все объекты клиента с договором, кассой и дебиторкой:
оттуда переходят в объект, этапы и расходы.

При создании объекта клиент ищется по имени или телефону, а если его ещё нет —
заводится прямо из формы, не выходя из неё.

## Оформление

Интерфейс собран по Material Design 3. Цветовые роли выведены из бирюзового
зерна документа ТЗ, но живут парами «контейнер + текст на контейнере», поэтому
контраст держится и в светлой, и в тёмной теме. Роли за пределами стандарта
две: `--positive` для приходов и `--auto` (янтарный) для строк, которые система
создаёт сама, — этот сигнал достался от ТЗ и его стоило сохранить.

Форма показывает то, без чего запись не сохранить; редкое — комментарий,
— свёрнуто под «Ещё». Валюта выбирается
значком: доллар или пачка наличных, тем же значком переключается показ в шапке.
Диалог прокручивается, а шапка с названием остаётся на месте.

Токены лежат в начале `app/assets/main.css`: цвет, форма (4–28 px), тени,
длительности и кривые движения. Компоненты — кнопки четырёх типов, чипы,
сегментированные переключатели, заполненные поля ввода, диалоги со скруглением
28 px, нижняя навигация с «таблеткой» под активным разделом.

Шрифт — Roboto, цифры набраны Roboto Mono с табличными знаками: суммы в
колонках выравниваются по разрядам.

Иконки — [Phosphor](https://phosphoricons.com) через `@nuxt/icon`. Набор стоит
пакетом, в сборку попадают только те 46 иконок, что реально встречаются в коде.

Размеры подняты примерно на пятую часть против первой версии: крупнее
иконки, шрифт, плитки и строки таблиц. Заодно убрано лишнее — цепочка
расчёта на этапе повторяла плитки, три полосы закрытия свелись к одной,
широкая таблица долей по этапам заменена карточками.

Движение: переход между страницами, появление карточек и плиток по очереди,
всплытие диалога, лист снизу на телефоне, слой состояния под курсором,
пружина у плавающей кнопки. Всё отключается при `prefers-reduced-motion`.

## Журнал изменений

У каждого объекта есть своя страница истории: `/objects/<id>/journal`, кнопка
«Журнал изменений» в карточке объекта. Там видно, кто, когда и что сделал —
создание и правка объекта, этапы и смена их статуса, каждая операция, бонусы,
сторно с причиной, закрытые обязательства, прикреплённые файлы, изменения
списка допущенных. Есть фильтры по разделу и по человеку, записи из раздела
«Операция» ведут на свой этап.

Источник — таблица `audit_log`, куда пишется каждое действие. Записи не
редактируются и не удаляются. Страница доступна владельцу и бухгалтеру:
в журнале видны суммы договора и ставка бонуса, а прорабу и участнику
их видеть нельзя (раздел 3 ТЗ).

## Показ сумм: USD / SUM

В шапке стоит переключатель **USD / SUM**. У каждой операции свой курс доллара
на её дату (`fx`, сумов за 1 $), и при показе в другой валюте каждая строка
пересчитывается **по своему курсу**, а итоги, доли и отчёты считаются заново
из пересчитанных строк (`shared/display.ts`). Операция, записанная в сумах,
в сумах показывается ровно так, как её ввели.

Сумма договора, суммы этапов, планы команд и выделения даты не имеют —
они пересчитываются по курсу объекта (или справочному, если у объекта курса нет).
В базе ничего не меняется: учёт ведётся в валюте объекта. Формы ввода
показывают и принимают суммы в валюте объекта.

**Курсовая разница.** Касса в сумах считается из строк, каждая по своему
курсу, поэтому у этапа, где в долларах касса ноль, в сумах может остаться
«12 000 сум». Это не деньги, а разница курсов — под кассой так и написано:
«в т. ч. курсовая разница». Долг в другой валюте считается из долга
в валюте учёта по курсу объекта: оплаченный этап показывает ноль.
Закрытие этапа проверяется в валюте учёта.

## Курсы валют

У объекта есть свой курс — сколько сумов за доллар. Он справочный: по нему
суммы пересчитываются на экране и подставляется подсказка в операции.

Любую сумму — договор, этап, план команды, сумма человека, выделенное на
этап — можно набрать хоть в долларах, хоть в сумах: рядом с полем стоит
переключатель валюты, под полем сразу видно «≈ 216 000 000 SUM по курсу
12 000». В учёт уходит сумма в валюте объекта.

У каждой операции поле «Курс доллара на дату, сумов за 1 $». Подставляется
**официальный курс ЦБ Узбекистана на дату операции** (cbu.uz): сменили дату —
курс подтянулся на неё. Его можно поправить, если меняли по другому курсу;
после ручной правки курс больше не подменяется. Курс ЦБ на день не меняется,
поэтому кэшируется навсегда (таблица `rates_cache`). Нет сети — подставляется
курс объекта, под полем написано «введите вручную».
Для пары USD ↔ UZS из этого курса сервер получает курс к валюте объекта.

Для других валют (не сумы и не доллары) курс к валюте объекта вводится
отдельным полем; подсказка — с `open.er-api.com`.

## Данные и копии

* База — один файл `.data/finance.db` (SQLite из стандартной библиотеки Node ≥ 22.18).
* Вложения — `.data/files/`. Тип файла проверяется по содержимому, а не по
  заголовку от браузера.
* Ежедневная копия — `.data/backups/finance-ГГГГ-ММ-ДД.db`, хранится 30 дней;
  вложения докладываются в `backups/files/`. Каталог копий задаётся
  переменной `FINANCE_BACKUP_DIR` — в продакшене направьте его на другой диск:
  копия на том же диске от поломки диска не спасает.
* Путь к базе переопределяется переменной `FINANCE_DB`.
* **Копия вне сервера — Telegram.** Задайте `FINANCE_TG_TOKEN` (токен бота
  от @BotFather) и `FINANCE_TG_CHAT` (id чата или канала, куда добавлен бот):
  ежедневная копия базы сжимается и уходит туда документом (до 50 МБ).
  Фото чеков туда не отправляются — для них держите `backups/files` на другом диске.
* За обратным прокси (nginx) задайте `FINANCE_TRUST_PROXY=1`, чтобы защита
  от подбора пароля считала попытки по настоящему адресу клиента.
* Записи не удаляются: ошибочная операция сторнируется, люди и категории
  уходят в архив. Все изменения пишутся в `audit_log`.
* Снятые с учёта люди и категории пропадают из выбора, но не из истории:
  их имена приходят отдельным списком, поэтому старые записи читаются.
